# 案例库

按月份归档的爆款笔记。**只存元数据和结构拆解，不存图。**

## 目录约定

```
cases/2026-10/
  01-观点卡-死磕几位大神/
    meta.json          ← 标题、赞藏评、图数、正文长度、正文开头、标签、结构原型
  02-清单图鉴-28个AI工具/
    meta.json
```

目录名前缀是**结构原型**，一眼能看出这条属于哪类：

| 前缀 | 原型 | 一句话 |
|---|---|---|
| `观点卡` | A | 1 张图 + 900 字正文，正文才是内容 |
| `清单图鉴` | B | 6–8 张，每页一层，收藏型 |
| `资料截图` | C | 3–7 张文档长图，信息密度型 |

## meta.json 字段

| 字段 | 说明 |
|---|---|
| `标题` / `赞` / `藏` / `评` | 页面显示值，约数 |
| `图数` | 轮播图张数 |
| `正文长度` | 字符数，用来判断属于哪种原型 |
| `正文开头` | 前 200 字，够看结构和语气，不整段复制 |
| `标签` | 话题标签，看选题覆盖 |
| `结构原型` | A / B / C |
| `结构要点` | 一句话说清它怎么组织的 |

## 怎么加新案例

**自动**（需要本机 CDP 代理 + 已登录的浏览器会话）：

```bash
python scripts/collect_cases.py \
  --keywords "AI工具,AI教程,提示词模板" \
  --limit 26 \
  --out cases/2026-11
```

跑完会得到一堆 `meta.json`，但 `结构原型` 是「待判定」—— **这一步脚本判不了，必须人看**。
打开笔记，看图数、正文长度、内页结构，填 A / B / C，再补一句 `结构要点`。

**手动**：照现有 `meta.json` 的字段建一个就行，没有强制格式校验。

## 为什么要按月份分

爆款有季节性。同一个题，三个月后再搜，头部会换人。
按月存，半年后能看出「哪种原型在变强、哪种在退潮」—— 这比单次快照有用。
